# Repository notes

- `ProyectoFinal.sln` contains the .NET 8 app (`ProyectoFinal/`, MVC + Identity Razor Pages) and `ProyectoFinal.Tests/`. `Program.cs` is the entrypoint; CRUD lives in `Controllers/` + `Views/`, login/roles in `Areas/Identity/Pages/`.
- From the root: `dotnet build ProyectoFinal.sln`, `dotnet test ProyectoFinal.sln` (EF InMemory; no SQL Server needed), `dotnet run --project ProyectoFinal/ProyectoFinal.csproj --launch-profile http` (`http://localhost:5092`). Tests can be focused with `dotnet test ProyectoFinal.Tests/ProyectoFinal.Tests.csproj --filter FullyQualifiedName~NavigationTests`.
- Local `appsettings.json` points to SQL Server 2025 named instance `Server=.\MSSQLSERVER01;Database=imprentacollantesbd` (17.0.1000.7); the default `MSSQLSERVER` instance still runs SQL Server 2022. It has no credentials. Optional `BootstrapAdmin:Email` + `BootstrapAdmin:Password` user-secrets provision an Admin at startup. See `README.md`; public registrations have **no CRUD access** until given Admin. Do not commit bootstrap credentials.
- The only registered EF context is `Data/ApplicationDbContext.cs`; `Models/DbContextNombre.cs` and `Areas/Identity/Data/ProyectoFinalContext.cs` are legacy/unregistered. CRUD uses `IdentityUser`, not scaffolded `Models/AspNetUser`.
- `Data/Migrations/*AddBusinessTables*` creates commercial tables in a **new** database; `WidenIdentityKeyColumns` upgrades Identity key columns. The existing business schema was baselined before widening Identity columns. On 2026-11-09 the database restored from `../bd_imp_avance.bak` on SQL Server 2025 received `20261108120000_TramosDescuentoProducto` after a verified backup in the instance Backup directory. Never run `AddBusinessTables` against another populated database without schema/history reconciliation; never auto-apply migrations on startup. Use `--migrate-only` explicitly after backup. SMTP settings in the restored database need the password reentered because the original Data Protection key is unavailable. `Services/FakeEmailSender.cs` is legacy/unregistered.
- Admin pages use `Areas/Identity/Pages/Shared/_PanelLayout.cshtml`; the public/auth shell uses `Views/Shared/_Layout.cshtml`. Design tokens are in `wwwroot/css/site.css` and `DESIGN.md`.
- `Documentacion/REQUERIMIENTOS_SISTEMA.md` describes **target** capabilities (orders, BI, AI, service layers), not the current implementation; verify behavior in `Program.cs` and code before treating it as existing architecture.
