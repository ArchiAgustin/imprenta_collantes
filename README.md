# Imprenta Collantes · sistema de gestión

Aplicación ASP.NET Core 8 para administrar clientes, proveedores y productos; emitir cotizaciones, confirmar ventas, seguir los trabajos del taller y consultar analítica operativa. Incluye un asistente opcional de pre-cotización conectado a Groq.

## Ejecutar el entorno local configurado

Se requiere el runtime ASP.NET Core 8 y una instancia SQL Server. La configuración local apunta a `Server=.\MSSQLSERVER01;Database=imprentacollantesbd` (SQL Server 2025) y no contiene contraseñas. Desde Visual Studio Code puedes iniciar el perfil `http` con la extensión C#; también puedes usar desde la raíz:

```sh
dotnet run --project ProyectoFinal/ProyectoFinal.csproj --launch-profile http
```

Abre `http://localhost:5092`. La base actual contiene `Archiagustinulloaruiz@gmail.com` con el rol `Admin`; el secreto de bootstrap no está configurado ni se necesita para iniciar. Cambia la contraseña antes de usar el sistema con información sensible. Nunca guardes contraseñas en `appsettings.json`.

## Límites actuales

- El registro público está deshabilitado: solo un administrador puede crear cuentas. Las cuentas nuevas nacen sin roles y no obtienen acceso a módulos hasta que el administrador las asigne. Si una cuenta tiene varios roles, utiliza uno activo por sesión; los permisos no se suman.
- Las cotizaciones admiten productos, cantidades y precios por línea. El servidor calcula subtotal, IGV del 18% y total. La vigencia predeterminada es siete días desde la emisión en fecha peruana; las vencidas se revalidan con revisión humana creando una cotización nueva vinculada. **Administración → Series internas** permite configurar serie, próximo correlativo y dígitos por tipo; las series iniciales son `C001-004532` para cotización y `V001-004532` para venta interna. Los documentos ya emitidos mantienen su numeración. Ambas se pueden imprimir en A4; la venta imprimible **no es un comprobante de pago tributario**. Consulta [alcance y preparación para una futura fase SUNAT](Documentacion/DOCUMENTOS_COMERCIALES_INTERNOS.md).
- Al confirmar una cotización vigente se crea una **Venta** y un **Pedido de taller** asociado en una sola transacción. Se valida y descuenta el stock de artículos; los servicios no usan inventario. Si falta stock, la confirmación completa se rechaza. La venta se puede cancelar y reponer stock solo mientras el trabajo siga `En cola`. Los cambios simultáneos entre cancelación e inicio del taller se resuelven por estado; la edición de productos usa `rowVersion` para detectar stock desactualizado.
- El taller avanza los trabajos en secuencia: `En cola` → `En impresión / acabado` → `Listo para recojo` → `Entregado`. `MenuSistema` admite menús, hijos y subhijos; `PermisoRolMenu` asigna ver/crear/editar/eliminar/procesar por pantalla sin herencia desde agrupadores. Los enlaces solo apuntan a destinos de la aplicación registrados en código. El rol activo `Admin` conserva acceso administrativo total.
- El administrador dispone de «Analítica»: filtra ventas **confirmadas** por fecha de confirmación en horario peruano (UTC−5), presenta ventas **con IGV** separando neto e IGV, excluye las canceladas y compara productos y clientes por importe. Cotizaciones se agrupan por fecha de emisión; taller y alertas de inventario muestran el estado **actual**. El panel incluye un **embudo de conversión** (emitidas → vigentes → convertidas → vencidas) y **KPIs de recurrencia**: clientes con al menos dos compras confirmadas en el periodo, porcentaje de recurrentes, ticket medio recurrente frente a nuevo, última compra, días sin comprar y frecuencia media calculada con todo el historial del cliente. El costo unitario sin IGV (compra para artículos, estimación para servicios) es opcional y se copia a cada línea cuando se confirma una venta. La utilidad estimada se calcula sin IGV únicamente para líneas con costo; se etiqueta **parcial** si faltan costos. No representa utilidad neta contable ni facturación tributaria.
- En «Nueva cotización» se puede abrir «Preparar desde solicitud con IA». Requiere el permiso **crear** del menú Cotizaciones. Correos, teléfonos, documentos y algunos campos identificables se ocultan localmente; el usuario debe revisar y aprobar el texto exacto que se enviará a Groq, ya que no se pueden detectar infaliblemente nombres o direcciones libres. No se consulta ni envía el catálogo de clientes. Nombre/DNI/RUC explícitamente etiquetados se extraen en el servidor, por separado del texto externo, y requieren confirmación para sugerir un cliente registrado. La respuesta de Groq se valida y solo se vincula un producto con coincidencia exacta y única; el usuario revisa cliente, presentación, cantidades y precios. No se guarda nada hasta «Guardar cotización». Sin API key, ante error/respuesta inválida o demora mayor a 5 segundos se mantiene la cotización manual. Límite: cinco solicitudes por usuario por minuto; no se guardan mensajes ni respuestas de IA.
- **Catálogos SUNAT** se consultan en Administración → Catálogos SUNAT. Los códigos fuente son de solo lectura; se permite activar/desactivar con auditoría y validación de referencias. La importación inicial excluyó errores, países, nacionalidades, catálogos laborales, motivos de nota de crédito de percepción y jerarquía `sun_*`, según el alcance acordado. No representa integración ni autorización de SUNAT.
- Al cargar el borrador asistido se muestran **referencias locales**, no generadas por Groq: precio mínimo por presentación sin IGV para un margen bruto del **10 %**, descuento máximo respecto del precio de catálogo y última venta confirmada en una presentación con factor comparable. Admin puede configurar tramos de cantidad y descuento sugerido desde el detalle del producto; si hay tramo y costo válido, el servidor muestra un precio recomendado que respeta el mínimo y considera el historial comparable. El vendedor elige el precio final. El mínimo se redondea **hacia arriba** al céntimo. Sin costo o tramo no se inventa una recomendación; el servidor valida el margen al guardar y confirmar la venta.
- La cotización se puede descargar como PDF A4 generado en el servidor; también se puede enviar al correo del cliente con ese PDF adjunto. El envío usa SMTP configurado por Admin en **Administración → Configuración → Parámetros**. La contraseña SMTP se cifra con ASP.NET Core Data Protection; si no se configura un servidor válido, no se entrega el correo. La guía para una cuenta personal de Gmail (verificación en dos pasos y contraseña de aplicación) está en [configurar el correo con Gmail](Documentacion/CONFIGURAR_CORREO_GMAIL.md). El PDF y la venta siguen siendo documentos comerciales internos, no comprobantes tributarios.
- El anillo de Data Protection se conserva entre reinicios en `%LOCALAPPDATA%\ASP.NET\DataProtection-Keys` (Windows, DPAPI del usuario actual) o `~/.aspnet/DataProtection-Keys` (Unix). En producción, fija `DataProtection:KeysPath` a una carpeta persistente con ACL restringida. En Unix producción configura además `DataProtection:CertificatePath` y `DataProtection:CertificatePassword` mediante variables de entorno/secrets para cifrar las claves en reposo. No borres ni reemplaces el anillo: invalida cookies y tokens de recuperación/confirmación. Incluye su respaldo en el plan de recuperación, protegiéndolo como secreto.
- `dotnet build ProyectoFinal.sln` compila la aplicación y `dotnet test ProyectoFinal.sln` ejecuta las pruebas regulares con EF InMemory. Para probar migraciones, traducciones y concurrencia con SQL Server, establece `PROYECTOFINAL_SQL_TEST_CONNECTION` con una conexión a `master` y ejecuta `dotnet test ProyectoFinal.Tests/ProyectoFinal.Tests.csproj --filter 'FullyQualifiedName~SqlServerWorkflowTests|FullyQualifiedName~InventarioSqlTests'`; esas pruebas crean y eliminan bases temporales aleatorias. La prueba de rendimiento analítico es de solo lectura y opcional: establece `PROYECTOFINAL_SQL_ANALYTICS_CONNECTION` a la base a medir y filtra por `FullyQualifiedName~SqlServerAnalyticsPerformanceTests`.

## Configurar Groq (opcional)

Sigue la [guía paso a paso para configurar la API key de Groq](Documentacion/CONFIGURAR_GROQ_API_KEY.md) fuera del repositorio, sin pegar la clave en el chat ni en el historial de la terminal. El modelo predeterminado es `openai/gpt-oss-20b`, compatible con salida JSON Schema estricta; puede cambiarse mediante `Groq:Model` solo por otro modelo compatible. La aplicación nunca envía la clave al navegador. **Sin clave, el asistente avisa y se puede cotizar manualmente.** Antes de usar datos reales revisa las políticas de privacidad aplicables al envío de texto revisado a un tercero.

## Planificación propuesta

El plan acordado queda así:

1. **Reglas operativas:** definidas para vencimiento de cotizaciones, conversión única, stock, cancelación, estados del taller, permisos y auditoría.
2. **Ventas, taller e inventario:** implementados y migrados en la base SQL local; probados con EF InMemory y con una base temporal SQL Server. Los dos productos existentes están correctamente clasificados como artículos.
3. **BI:** panel de analítica y costos históricos implementado, migrado en la base local y probado con EF InMemory y una base temporal SQL Server. El indicador se llama «ventas confirmadas», no «facturado»; se agrupa por fecha de confirmación y se muestra con IGV. Registrar los costos reales de los dos artículos permitirá calcular utilidad de nuevas ventas; no se inventan costos anteriores.
4. **IA y precios:** pre-cotización asistida con Groq, revisión humana, anonimización previa y alternativa manual implementadas y probadas con un proveedor simulado. La llamada real requiere una API key que debe configurar el responsable del entorno. Las sugerencias de precio son locales y usan costo/historial comparable; no existe optimización predictiva de cierre ni recomendación de Groq sobre precios.
5. **PDF y correo:** PDF de cotización A4 y envío SMTP con adjunto implementados. Para habilitar la entrega real, el responsable debe completar y probar SMTP en Parámetros; no se guardan credenciales en el repositorio.
